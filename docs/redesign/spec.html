Fadeno

A meta-harness for common subagent workflow patterns, neutral across harnesses and models. It routes work to models by role, wraps the spawn with deterministic scaffolding, and keeps a record nobody has to think about. Everything else is the intelligence's job.

This document specifies behaviour, not implementation. Every call in it has been made and reviewed; nothing is left open.

Draft 8 also settles the command-lane close/report race: a dispatch cannot close itself, only a stopped row is report-ready, and a close-only dead process is settled and reconstructed from its output. It retains Draft 7's explicit baseline rule: a --from dispatch name or id follows the ledger only to the reachable branch of an isolated dispatch; its recorded opening base is never a recovery substitute, and a shared-tree dispatch cannot supply a retained result. Literal Git refs and SHAs remain valid. Cross-namespace and dispatch-name/ID-prefix ambiguities refuse rather than guess. Invalid explicit baselines and later isolated-worktree failures refuse rather than silently creating shared-tree dispatches, and --shared --from is rejected before prompt handling. Draft 5's Codex first-use and lifecycle revisions remain: host activation reconciles model-neutral archetype names; unclosed dispatches are advisory; reviewed is neutral; and a clean stopped worktree may be removed independently of closure.

01What Fadeno is for

The user is someone constantly splitting and routing work between different models on different harnesses, who needs structure without ceremony. Fadeno gives them four things and deliberately nothing else:

  • Routing. Name a model once; point roles at it; change the binding at user, repo or session scope with one command.
  • Spawning. Launch subagents from inside a host session, on the right model, in a scaffolded environment.
  • Logging. A durable record of what was delegated, on what, and how it ended — written without anyone asking for it.
  • Context. The host knows how to use Fadeno; each subagent knows its own job.

Complex environment setup, merge judgment, conflict resolution and workflow structure are not Fadeno's work. They belong to the intelligence, which has context Fadeno cannot have.

02Ontology

archetype
A role you point at a model: worker, reviewer, judge, scout, director by default. The set is open — users define their own. Each carries a natural-language description that tells a director when to reach for it.
dial
The binding from an archetype to a model and effort, at user, repo or session scope. A dial may also point at another archetype, carrying its model and effort together.
harness
A coding agent Fadeno can work with. A host harness is one Fadeno can observe spawns inside; a driver harness is one Fadeno can launch as a process. A harness may be both.
lane
How a dispatch is delivered. Host lane: a subagent inside the caller's session. Command lane: a process Fadeno spawns. The lane is chosen by Fadeno and is invisible to the host.
dispatch
One unit of delegated work. Has a UUID, a semantic name, a worktree, and exactly one terminal decision.
worktree
A git worktree on its own branch, cut from HEAD or a named ref, where a dispatch does its work.
ledger
The append-only record at .fadeno/dispatches.jsonl. Three row types; nobody writes to it by hand.

03Routing

Resolution

  • An archetype resolves to a model and an effort, by walking the merged dial map across scopes — most specific scope wins per key.
  • A dial pointing at another archetype is followed to a terminal model. An alias carries model and effort together. Wanting the same model at a different effort means a separate route, not a partial alias.
  • Aliasing binds routing, never meaning: an aliased archetype keeps its own description.
  • Cycles are refused at set time and at resolve time — a cycle can be formed across scopes by two edits that are each individually valid.
  • An archetype with no dial resolves to host: the host session's own model. This has no edge case — no dial means no model, therefore no harness, therefore host lane. (Named current-host until 0.7; the old spelling is still read and answered as host.)

Visibility

Routing is invisible by default. The host asks for an archetype; Fadeno resolves and applies model and effort without the host thinking about it. Two escape hatches exist and are not encouraged: fadeno dial resolve for inspection, and an explicit model override on a spawn — the real case being a director escalating a task that keeps failing.

Vocabulary is snapshotted; routing is live

This distinction governs when anything must be re-run, and it must not blur.

  • Descriptions are injected when a host session activates, so adding an archetype or editing a description requires re-activation. The CLI says so on those changes — and only those.
  • Dials are resolved at spawn time and are always current. Changing a dial requires nothing.
  • Fadeno stamps a catalog fingerprint at activation and reports staleness at the next spawn, so an ignored advisory or a teammate's edit still surfaces.
  • Codex requires user-scoped agent files before custom archetype names appear in its spawn schema. The first $fadeno-host activation reconciles minimal name-and-description files; if they changed, Codex sees them in the next fresh session. They contain no model or effort.
  • Provider model churn never rewrites agent files. host follows the current session model; named models resolve from the live catalog, and models verify reports a backend that no longer lists one. With no ref it follows effective archetype dials; an explicit registry alias or identity can verify an undialed model. There is no silent fallback.

04Spawning

Fadeno wraps every spawn with deterministic scaffolding. On the host lane the wrapper is a hook; on the command lane it is the CLI itself. Both do the same four things.

The spawn wrapper

  1. Resolve the archetype to a model and effort, and apply them to the spawn.
  2. Choose the lane — host if the resolved model can be delivered in-session, command otherwise. The host is not told which.
  3. Cut a worktree on a branch, from HEAD or a named ref, and record its path, branch and base. An explicit --from dispatch name or id resolves through the ledger only to that dispatch's reachable isolated branch; its opening base is never substituted, and a shared-tree dispatch cannot supply a retained result.
  4. Inject the worker's contract into the prompt, and write the opened row.

On the host lane the hook applies model and effort by rewriting the spawn. Where the resolved model can only be reached as a process, the hook instead redirects the spawn to a dispatch proxy — a minimal agent whose only job is to invoke the command lane. The host observes no difference.

The proxy is the design on every harness, not a fallback. A hook may turn out to be able to invoke the command lane directly on some harness; the design does not assume it, and does not vary by harness where it can. One path that works everywhere beats a faster path that works in one place — the same reasoning that put the worktree contract in the prompt rather than using Claude's native isolation.

The worktree

  • Cut from HEAD or a named ref — never from dirty state. Git cannot check out uncommitted work, and replaying it is complexity nobody needed: if a worker requires uncommitted work, the host commits first or requests a shared tree.
  • On a branch, named fadeno/<semantic-name>, so the ledger and git agree on one identifier and a forgotten dispatch is findable by git branch alone.
  • The command lane uses a worktree too, under the same rules — and more easily, since Fadeno sets the process's working directory directly.
  • An explicit --from accepts a dispatch name/id, an existing Git ref, or a commit SHA. A shared dispatch or an unavailable branch/result is refused with instructions to commit the desired state and pass its Git ref or SHA. A value matching both namespaces, or an exact dispatch name matching another dispatch's id prefix, is refused; qualify a Git ref such as refs/heads/main or use the dispatch's full UUID. If it cannot resolve, the spawn is refused before prompt handling or opening; --shared --from is rejected as incompatible before prompt handling; if isolated worktree creation later fails, it is also refused rather than abandoning the requested baseline in a shared tree. With no explicit --from, an environmental git worktree add failure may still proceed in the shared tree and the prompt says so.
  • A shared tree remains available on request. When one is requested while another shared dispatch is open, say so — that is the only collision git does not solve.

Branch-name sanitization is deliberately dumb: lowercase, replace runs of anything outside [a-z0-9._-] with a single -, trim to 60 characters. A collision created by the trim is just another collision, handled by the duplicate counter that already exists. No cleverness, because a surprising branch name is worse than an ugly one.

05The three contracts

What the worker is told

  1. Its worktree path and branch, and that modifications and commits belong in that assigned tree. A caller-authorized read-only inspection outside the assigned tree is allowed.
  2. That the caller's task and its archetype determine the duty: implementation and integration tasks make the requested changes, commit them, and before finalising on an isolated branch merge from upstream and resolve conflicts in its own tree.
  3. That a report-only task (such as review, exploration, or judging) changes nothing, fabricates no commit or merge, and recommends reviewed; a director coordinates children and integrates accepted child changes when its task calls for it.
  4. That its return message must state what is in the worktree, including anything untracked, and recommend the disposition appropriate to the task.
  5. If it delegates, it must never close the dispatch it is currently running in: that dispatch returns its report to its caller/host. It may close only child dispatches it opened, after reading their reports.

What the host is told

  1. The dispatch's UUID and semantic name, at spawn and again at stop where the harness allows.
  2. That the worker's report is a recommendation to weigh, not a finding to accept — read it and reach an independent conclusion.
  3. Every unclosed dispatch in this repository, at each spawn, with the insistence that it be reviewed and closed; each host user turn also receives a compact reminder of stopped dispatches awaiting a decision.

What closing requires

Exactly one verb: merged, kept, discarded, failed, or reviewed, with an optional note. reviewed is neutral and report-only: it records that the report was read without claiming what happened to the work. Fadeno performs no merge — the host does, or delegates it. The requirement is that the decision be made, not that Fadeno make it.

The nag

  • At every spawn, the host is reminded of all unclosed dispatches by UUID and name; at every host user turn it receives a compact reminder derived from the current ledger, naming stopped dispatches awaiting a decision.
  • Unclosed dispatches are advisory state. There is no unclosed-count threshold and no spawn refusal derived from the ledger.
  • Scope is repository-wide, not session-wide. A director that spawns three workers and exits leaves dispatches with no owner; session scope would hide them permanently — exactly where nesting happens. Grandparents inherit orphans.
  • Reporting targets the stop hook where a harness supports it, and goes into the nag regardless. The nag is load-bearing; stop-time reporting only makes the news arrive sooner.
  • When a worker's working directory did not match its assigned worktree, say so — at stop and in the nag.

An older unclosed_limit catalog key may be read for compatibility, but it is retired and ignored. The ledger remains repository-wide so a fresh host can recover work another session left behind.

06Context delivery

  • A host session receives the archetype vocabulary and Fadeno's rules when it activates host mode.
  • A spawned director receives the same content injected into its prompt. A director never activates host mode, yet it is the archetype most needing the vocabulary — its job is choosing what to spawn next.
  • Both come from one source, so they cannot drift.
  • Injected content is the archetype list, routing behaviour, the worktree contract and the close obligation — not setup prose. General rule: if an intelligence can spawn, it needs the vocabulary.
  • Host activation may perform the narrow Codex vocabulary reconciliation before injecting that content. It does not link a CLI, probe providers, or edit another harness's settings.

07The ledger

Three row types, because "started", "the agent stopped" and "the host decided" are three facts, recorded by three parties, at three times. Nothing here is written by hand.

# opened — by the wrapper
id · name · at · session · parent · archetype · model · effort
explicit_model · lane · harness · workspace{path,branch,base} · task · prompt · process_group

# stopped — by the stop hook, an outside observation
id · at · final_message · dirty · model_observed · evidence

# closed — when the host decides
id · at · verb · note
  • parent is load-bearing: without it, "which dispatches did this director open?" is unanswerable and orphan inheritance cannot be computed.
  • task holds the first ~300 characters of the caller's prompt, flagged when truncated. prompt points at the full text at .fadeno/prompts/<id>.md.
  • Prompts live outside local/ so clean cannot orphan the rows that reference them. They are evidence of what was asked, not scratch. Unbounded by design.
  • The log records what was asked, never what Fadeno injected — injected text is identical every time, so storing it would make the log describe Fadeno instead of the work.
  • final_message records presence, never completeness. On Claude's interrupted path the harness supplies no message at all, so its absence says nothing about whether work finished.
  • model_observed is the model the agent reported running on, read from its transcript at stop and recorded beside the one the dial asked for. It is the only way to catch a harness that ignored the model a spawn passed — the failure mode that has no other symptom. Absent when the harness reports none; never inferred from the dial, which would make it agree by construction.
  • process_group is command lane only: the process group Fadeno launched, recorded so cancel has something to signal. Absent on the host lane, where the subagent belongs to the harness.

08Command surface

CommandDoes
dialShow, set and resolve archetype bindings. With no arguments, lists archetypes with descriptions and resolved models — the director's reference.
modelsInspect the registry; verify dialed deliveries or explicit registry aliases and identities against their backends.
dispatchList, inspect, or run a dispatch. The legacy --archetype/--model launches remain valid; dispatch run <archetype-or-model> resolves one positional selector against the effective archetype names and registered model references, refusing an exact match in both categories. The read forms use the same implementation as the compatibility dispatches spelling.
dispatch-waitWait for a stopped row, then print the report. A closed-only row is not terminal: a live command group remains running, and a dead group gets the settle window before the stop is reconstructed from its output, stderr and worktree. The direct launcher still returns stdout when close precedes stop.
dispatch-openThe spawn wrapper used by the hooks before a Claude spawn or at Codex subagent start. Resolves, decides the lane, and either opens it on the host lane — worktree cut, row written, the contract-bearing prompt returned — or relays it: nothing opened, the prompt staged, and the dispatch call the proxy should run handed back. The Codex host hook delivers the contract at SubagentStart. The hook writes no ledger or repository evidence itself; its separate pending scratch is only the mechanical event bridge.
prompt-stageStage plaintext in expiring repository-local scratch for a Codex spawn whose message may be encrypted. An optional semantic name becomes a lowercase slug plus opaque lowercase token in the schema-safe task_name; the hook atomically consumes a repository-bound token once. The plugin handoff reservation is exclusive for a session/archetype because Codex exposes no common event id. No ledger row, worktree, or prompt evidence exists until the ordinary dispatch path opens.
dispatch-stopRecord that a host-lane agent stopped. Given the agent's transcript it finds the dispatch from the contract header in its prompt, takes the last assistant turn as the final message when the harness passed none, and records the model the agent ran on. The stop hook uses a durable first receipt before optional Git inspection; a later idempotent replay may append dirty paths, ignored paths, and branch measurement as enrichment. For recovery, host guidance prefers saving an already-received final response and passing --message-file; stdin remains supported. A transcript with no contract is not a dispatch, and nothing is recorded. If the hook cannot record the receipt, it returns an actionable system message.
dispatchesCompatibility alias for the dispatch list, detail, and report reads; show one; find output by UUID or name.
logsRead the command-lane internal activity stream from the stderr path derived from the dispatch id. --tail <lines> prints the latest positive number of lines; --follow prints existing bytes and waits for appended bytes until a stopped row arrives and the file is drained. Host-lane dispatches have no Fadeno activity file because their harness owns that transcript; clean may remove command-lane scratch.
dispatch-closeRecord the terminal decision for a dispatch. The neutral reviewed disposition acknowledges a report without inferring a Git outcome. A process whose FADENO_DISPATCH_ID names the target is refused; its caller/host closes it, while a parent may close a child it opened.
cancelStop a running command-lane dispatch by signalling its process group. The direct signal is the fast path; when the caller is denied with EPERM, it places a per-dispatch request in .fadeno/local for the live launcher to consume from its own context. Cancellation succeeds only after that acknowledgement and group exit; an unconsumed request or still-live group is an actionable failure, never a stopped row. The dispatch still needs closing. On a host-lane dispatch it refuses and says the subagent is the harness's to stop.
worktreesReport worktrees holding unmerged work. The cross-session safety net.
contextPrint what a host session is told: the archetype vocabulary with live routing, the rules, every unclosed dispatch, and the compact ledger-derived host-turn reminder. One source for the host-mode hook, a spawned director's prompt, and a person who wants to read it (§06).
statusEffective routing, harness integration, and whether anything needs attention.
cleanRemove machine-local scratch — clean, readable worktrees of stopped or closed dispatches (and unknown worktrees), plus outputs; never prompts or the ledger. Open/running, dirty, unreadable, and unregistered paths remain protected, and branches stay.
pluginGenerate the harness plugin from this checkout.
setupOptionally link the CLI onto PATH. A symlink, never a copy — one copy makes version skew structurally impossible. Its narrow --codex --agents-only operation is invoked automatically by Codex host activation and changes only Fadeno-managed archetype files.
completionShell completion.

Codex delivers the host contract at subagent start. Before an archetype spawn, the host resolves the bundled launcher as setup does, stages the exact task with prompt-stage --name <semantic-name> --prompt-file <file> --json (or stdin), and places the returned schema-safe task_name on the spawn, alongside the live model and effort from the archetype dial. PreToolUse atomically reserves one same-session/same-archetype handoff and validates routing; SubagentStart claims the repository-bound reservation before reading plaintext, then calls the CLI to open the dispatch, cut the worktree, bind the agent id, and deliver the contract through additionalContext. A second uncorrelated start is refused before the agent exists, while impossible recovery states receive a sealed fallback. A readable prompt without a staged token remains supported for older Codex versions. A command-lane resolution uses the recovered plaintext to stage and return the fadeno dispatch command for the host to run. Codex native subagent threads have a runtime concurrency limit; command-lane processes do not consume native slots.

The lane is decided in one place and by one bit. dispatch-open resolves the archetype and asks whether this session can deliver the resolved model itself; everything else follows. A host-lane answer opens the dispatch there and then, because the hook that asked is about to spawn the agent. A command-lane answer opens nothing — the prompt is staged and the caller is handed the dispatch command — so a proxy that never runs leaves no row behind. --lane host and --lane command force the answer for a caller that already knows; they are for the hooks, not for people.

worktrees is its own verb rather than a section of status. It is the report someone runs deliberately when they suspect work was forgotten, and burying that in a status wall makes it easy to skim past — which is the exact failure it exists to catch.

09Non-goals

Named explicitly, because each was in the product and was removed for a reason. Anything here must argue its way back in.

Fadeno does not

  • Structure workflows. Playbooks, gates, run ledgers and repair loops are gone. A workflow is a sequence of dispatches, which the intelligence composes. They may return as a plugin above this layer.
  • Adjudicate models. No shadow pairs, no blinded judging, no bakeoff.
  • Enforce or attest. No prompt digests, no relay attestation, no tamper detection, no verify. The ledger records; it does not police.
  • Materialize routing into agent files. Model and effort are set at spawn time. Codex gets only the user-scoped name-and-description files its spawn schema requires; they carry no model or effort and are reconciled at host activation. Fadeno reports rather than overwrites a hand-created same-named agent file, because its model could silently override what a spawn passes.
  • Police concurrent writes. No window log, no overlap stamps, no lease, no lock. Worktrees and real merges remove the shared-tree world that machinery existed for.
  • Impose deadlines. Nothing Fadeno launches is killed on a timer. A person may stop it — that is cancel — but Fadeno never decides to on its own.
  • Decide what work is worth keeping. It never destroys a worktree holding uncommitted work, and never judges whether output matters.
  • Diagnose itself. No doctor. With nothing materialized, no second CLI copy and no run ledgers, there is nothing to diagnose.

10Harness support

A harness is a host harness if Fadeno can observe spawns inside it — which in practice means Claude-or-Codex-compatible hooks. Everything else is a driver harness, reached through the command lane, which loses nothing: the command lane is where Fadeno controls the process outright.

HarnessHostDriverNote
claudeyesyesShips Node; hooks work out of the box
codexyesyesHook trust is a prerequisite for host use, and users must know it
ompyes—Reuses Claude-style hook manifests
grok, opencode, muse, agy—yesDriver-only

Fadeno remains an npm package. Six of seven harnesses ship no Node, so those users install a runtime their harness does not otherwise need — accepted for now, revisited if a real user objects.
