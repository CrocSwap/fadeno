Scope — what the product is

01

Playbooks are cutcut

Evidence, not preference: the last playbook run in this repo was 2026-09-05, both field-report repos used ad-hoc dispatch exclusively, and the day's 30 commits touched dispatch code 36 times against playbook code 6. They may return as a plugin on top — a playbook is a sequence of dispatches with gates, which is the correct dependency direction. Extract the progress-sidecar wiring and parallel-worktree logic from drive.ts before lifting the shell out; the ad-hoc path needs both and never had them.

02

Bakeoff and shadow pairs are cutcut

A model-evaluation apparatus sharing only the routing layer. Nothing in "split and route work between models" requires proving which model is better.

03

verify, attest, evidence are cutcut

2,954 lines. verify's fifteen checks audit run ledgers, which stop existing with playbooks. attest had a subagent record its own delivery; the stop hook now records the same facts from outside, which is strictly better evidence. evidence promotes a verified run receipt — a pure playbook concept.

04

Setup verbs collapsecut

init (472) had nothing left to seed but one config file — that is a first-run auto-create, not a command. vendor and unvendor vendored playbook definitions. clean stays, and matters more now that worktrees are the unit of work.

05

doctor goes; two checks fold into statuscut

Fifteen of its twenty checks inspect Fadeno's own state — runtime skew, steering drift, persisted-state schemas, the lease, overlap snapshots. Every one is downstream of something else being cut. What survives is "does my dial resolve to something real" and "are there worktrees with unmerged work."

06

Clean break, no migrationdecided

0.6.0 is published and two repos run it. Design without the burden of the past; fix those projects when it bites.

07

Stays an npm package, with exactly one copykeep

There are currently two byte-identical copies of the CLI on disk — the managed runtime and the plugin bundle — and roughly 1,559 lines exist to reconcile them. Make setup write a symlink rather than copy, and skew becomes structurally impossible: version comparison, managed-older/newer/divergent, the stamp marker and preferred-cli all evaporate.

Routing

08

The archetype set is opendecided

Users define their own, each with a model binding and a natural-language description the director reads to choose. Canonical seed: director, judge, reviewer, scout, worker. generator becomes scout — clearer, and it had exactly one reference in the entire codebase. The canon set stops being a constraint and becomes defaults, so the suppressedCanonArchetypes warning goes with it.

09

An archetype can route to another archetypedecided

Pin scout → worker and one command re-points both. The alias carries model and effort together; wanting the same model at a different effort means a separate route, not a partial alias. Aliasing binds the routing, never the meaning — an aliased archetype keeps its own description, because the description says when to reach for it and the dial says what runs it.

10

Cycles refused at set time and at resolve timedecided

Both, because a cycle can also be formed across scopes by two edits that are each individually valid. Resolution walks the merged map, not one layer — which is what makes cross-scope aliasing work: user says scout → worker, repo says worker → terra, scout resolves to terra.

11

An unbound archetype resolves to current-hostdecided

Reuses a slot that already exists. It also resolves cleanly by construction: no dial means no model, therefore no harness, therefore host lane. There is no edge case to write down. A director inventing an archetype name gets the host's own model rather than a dead turn.

12

Routing is invisible by defaultdecided

The host spawns an archetype; the hook resolves and rewrites model and effort without the host thinking about it. dial resolve stays available for inspection, and an explicit model override is exposed but not encouraged — the real case is a director escalating a task that keeps failing.

13

Vocabulary is snapshotted; routing is livedecided

The distinction the spec must state plainly. Archetype descriptions are injected at /fadeno:host activation, so adding an archetype or editing a description needs a re-run. The dial is resolved by the hook at spawn time and is always current, so changing a dial needs nothing. The CLI advises a re-run on catalog changes only — never on a dial change. The hook stamps a catalog fingerprint at activation and mentions staleness in its next spawn message, which catches the case where the advisory is ignored or a teammate changed the catalog.

Agent files and lanes

14

Materialized agent files are cut entirelymeasured 2026-09-07

The experiment that decided it: in an isolated CODEX_HOME with no agent file anywhere, a parent on gpt-6-astra/medium spawned a subagent that ran on gpt-5.6-luna/xhigh — both halves of the identity, set at spawn time via collaboration.spawn_agent. The documented precedence is explicit spawn value → [agents] default → parent; a file overrides all of it only when a file exists. So don't write files.

15

steering apply ceases to existcut

With nothing materialized, nothing goes stale. That deletes codex-agent-file.ts (967), most of steering.ts (2,403), the opencode and omp steering modules, the tampered/outdated/shadowed/unmanaged verdict ladder, digest stamping and verification, and the codex-agents doctor check — and retires the standing chore of re-running applies.

16

A hand-created agent file must be reporteddecided

The corollary of 14, and the one thing that can silently defeat routing: a file at .codex/agents/worker.toml beats whatever the host passes. Fadeno should notice and say so. Five lines, not a subsystem.

17

Host harnesses and driver harnesses are distinct in the ontologydecided

Different harnesses are supported as each. A harness qualifies as a host harness only if Fadeno can observe spawns there — on Codex that means hook trust is a prerequisite, and users have to know it. Where there is no hook system, the host lane is unloggable and the command lane is the answer.

18

The lane is arbitrated by the hook and invisible to the hostdecided

The host asks for an archetype. The hook resolves it and either rewrites model and effort for a host-lane model, or rewrites the spawn to target a dispatch proxy that runs the command lane. The host never learns which happened. Dispatch proxies therefore stay — they are the command-lane vehicle, and they can be far thinner than today's, since relay attestation policed a trust boundary that is being removed.

Worktrees

19

Cut from HEAD or a named ref — never from dirty statedecided

The host prompt says so plainly, and says the alternative: if a worker needs uncommitted work, commit first or use a shared tree. This deletes workspace-baseline.ts (438) and the whole "the workspace had moved, rebased onto it" path. Supporting evidence: every one of the nine dispatches this session was cut from a clean tree, so the replay machinery was load-bearing zero times in the workload it was built for.

20

On a branch, with a real mergedecided

Not detached, and not a patch apply. History survives, and a forgotten worktree leaves recoverable commits on a named branch instead of garbage reachable only through the worktree registration — which is what the five orphans from August actually are.

21

The agent owns the work; the host owns the decisiondecided

The worker works, commits, and merges from upstream and resolves conflicts in its own tree before handing back — the PR-owner model. Today conflicts land on the host instead; five did this session. It returns a suggestion covering what is in the worktree including anything untracked, and where it should be merged or discarded. The host is instructed to read the suggestion and reach its own conclusion. A subagent structurally cannot merge — it does not own the parent tree and exits before the parent acts — so merge-back is the host's job either way.

22

The overlap and concurrent-write system is cutcut

1,473 lines that existed to police concurrent writes to one shared tree. Worktree-default plus real merges removes the world it was fixing. The residual is real but small: two concurrent shared-tree dispatches still collide and git does not help. The proportionate answer is a warning at dispatch time — "another shared-tree dispatch is open" — not receipt stamps reconstructing it afterwards.

27

The hook cuts the worktree; the prompt carries the contractmeasured 2026-09-07

Claude has native isolation: "worktree" that creates a worktree on a branch and pins the subagent's cwd — elegant, and Claude-only. Codex has nothing equivalent: collaboration.spawn_agent accepts exactly fork_turns, message, model, reasoning_effort, task_name — no cwd, no worktree, and no worktree tool at all (its 40 worktree strings are the embedded gix git library). Supporting two mechanisms is the burden this redesign exists to remove, so: Fadeno's hook cuts the worktree, and the injected prompt tells the agent to work there. One mechanism, every harness.

28

The semantic name becomes the branch namedecided

Falls out of 27 for free: because Fadeno creates the worktree, it names the branch — fadeno/<semantic-name>. The ledger and git then agree on one identifier, and a forgotten dispatch is findable with git branch --list 'fadeno/*' even if the ledger is lost or the repo is cloned elsewhere. A second independent record of the same fact, at no cost.

29

Working outside the assigned worktree is detectable, and reporteddecided

The cost of a prompt-carried contract is that an agent can ignore it and work in the shared tree — the collision the overlap system was deleted to stop policing. But the stop hook receives cwd: if it does not match the assigned worktree, say so, at stop and in the nag. A statement of fact, not a rule. And when git worktree add itself fails, allow the spawn and say so in the prompt — "no worktree was created, you are in the shared tree" — rather than deny, which would turn an environment problem into a dead turn.

Lifecycle

23

Every dispatch gets a UUID and a semantic namedecided

Both reported at agent start and stop, both accepted as a tag, both shown in the nag. The host is encouraged but not required to supply a name; the default is <archetype>-<4 hex> — mechanical and never misleading, unlike a slug derived from task text. Reused names take a duplicate counter, scoped per repo.

24

Close is required, and nagged into existencedecided

Verbs: merged / kept / discarded / failed. At each spawn the host is reminded of every unclosed dispatch and pressed to review, evaluate and close; at five unclosed the next spawn is refused until it does. Threshold is wired for config but not exposed. Why the ritual matters: nine dispatches this session were opened and closed with zero forgotten, against five August orphans from a path that never forced the question. The value was never the merge logic — it was the mandatory question.

25

The nag is repo-wide, and grandparents inherit orphansdecided

A director that spawns three workers and exits leaves dispatches with no owner. Session-scoped nagging would make them invisible forever — exactly where nesting happens. Repo-wide scope surfaces them to whoever spawns next; orphans are reported at subagent stop where the harness allows it, and at nag time regardless.

26

A spawned director receives the host vocabulary and rules in its promptdecided

A director is a subagent, so it never invokes /fadeno:host — yet it is the archetype most needing the vocabulary, since its job is choosing what to spawn next. The hook injects it. This consolidates the fadeno-host skill and briefs/director.md into one source with two delivery points, so they cannot drift. Injected content is the archetype list, routing behaviour, the worktree contract and the close obligation — not setup prose. General rule: if an intelligence can spawn, it needs the vocabulary.

30

The log records what was asked, not what Fadeno addeddecided

The caller's prompt is the record; the hook's injected portion is not. That injected text is identical every time — vocabulary, worktree contract, close obligation — so storing it would make the log describe Fadeno instead of the work.

Stored in two places, for a measured reason. Prompts here average 10,705 bytes against a ledger row of ~850, so inlining them in full is a 12× ledger read on every listing. So: task carries the first ~300 characters inline, flagged when truncated — prompts lead with the ask, which is what makes a row recognisable when scanning — and prompt points at the full caller text.

Full text lives at .fadeno/prompts/<id>.md, not under local/. That move is the entire fix for a lifetime trap: clean wipes local/ and not the ledger, so the sidecar pattern used today would leave rows pointing at files clean deleted. Prompts are evidence of what was asked, not scratch.

Unbounded, deliberately. A few thousand dispatches is tens of megabytes on disk and nobody will care for a long time; clean can grow a --prompts mode if anyone ever does. Inventing a retention policy nobody asked for is how the window log got compaction, rotation and three doctor checks — all of which this redesign deletes.

The last three

31

The command lane uses a worktree toodecided

Same rules as the host lane — cut from HEAD or a named ref, on a branch named for the dispatch, contract carried in the prompt. Easier there than on the host lane, in fact: Fadeno spawns the process and sets its cwd directly, so the worker starts in the right place rather than being asked to go there.

32

Post-agent reporting targets the stop hook, but never depends on itdecided

Whether SubagentStop can surface a message back to the parent is unverified on both harnesses — PreToolUse's systemMessage is proven, the stop contract is a different one. So the spec plans for it: report at stop where the harness allows, and into the nag regardless. The nag is the load-bearing channel; stop-time reporting is an optimisation that makes the news arrive sooner. Designing it the other way round would put the whole close ritual on an unverified capability.

33

Host harnesses are Claude, Codex, and anything hook-compatible with themdecided

This gives the host/driver ontology a concrete test instead of a judgement call: a harness is a host harness if Fadeno can observe spawns there. Claude and Codex are confirmed; omp qualifies because it already reuses Claude-style hook manifests. Everything else in the catalog — grok, opencode, muse, agy — is driver-only and reached through the command lane, which loses them nothing: the command lane is where Fadeno controls the process outright.
